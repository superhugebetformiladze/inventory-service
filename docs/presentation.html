Зачем

Данные были, пользоваться ими было нельзя

Система мониторинга отдаёт XML-выгрузки. Внутри есть всё, но в виде, пригодном только для машины: длительности строками, станки — идентификаторами, данные продублированы в двух разных методиках учёта.

Как было

  • Файл открывается текстовым редактором, поиск — глазами
  • Длительность записана как PT6H52M37S, сложить её вручную нельзя
  • Станок обозначен как MDM-C19-002147500&36 — без названия и цеха
  • В одном файле два параллельных набора данных, их нельзя складывать вместе
  • Выгрузки перекрываются по датам — при сведении за месяц часы задваиваются
  • Ответ на вопрос «какая загрузка у станка за месяц» — несколько часов ручной работы

Что требовалось

  • Загрузка выгрузок через браузер, без доступа к серверу
  • Показатели сразу после загрузки, без подготовки данных
  • Разрезы: по станкам, состояниям, сменам, суткам
  • Понятные названия станков вместо идентификаторов
  • Просмотр как по отдельному файлу, так и по произвольному диапазону дат
  • Вход по логину, разделение прав: администратор и наблюдатель
  • Установка на внутренний сервер предприятия
Результат

Что получилось

Веб-приложение из трёх контейнеров: интерфейс, сервер приложения и база данных. Разворачивается одной командой.

Загрузка выгрузок

Коэффициент загрузки, структура времени по группам состояний, динамика по суткам, матрица «станок × сутки», таблица записей.

03

Страница станка

Паспорт, показатели за период, место в парке, структура времени, динамика по суткам, разбивка по состояниям.

04

Карточки оборудования

Паспортные данные загружаются из Excel и подставляются вместо идентификаторов во все отчёты.

05

Фильтры и экспорт

Период, методика учёта, смена, набор станков. Текущая выборка выгружается в CSV одной кнопкой.

Доступ и роли

Вход по логину и паролю. Администратор загружает данные и ведёт пользователей, остальные только смотрят.

Данные

Что внутри выгрузки

Формат XmlDataWrapper: справочники и таблица фактов в одном файле. Парсер приводит всё к плоским структурам и раскладывает по таблицам базы.

СекцияЧто содержит
DateLastReplicationКогда выгрузка сформирована и за какой период
MachineСтанки: внутренний ID и IntegrationID
MachineParamСостояния: работа по программе, простой, наладка, авария — и цвет каждого
GroupParamГруппы состояний: Тмаш, Тпрос.орг, Тобсл…
rep_MonitoringByPriorityОсновные данные: станок × состояние × сутки × смена и длительность
SheduleMeta / SheduleBaseГрафики смен и их границы

Что пришлось разбирать отдельно

  • Длительности в формате ISO-8601: PT6H52M37S → 24 757 секунд
  • Цвета состояний заданы знаковым числом .NET — переводятся в обычный цвет интерфейса
  • Идентификатор станка MDM-C19-002147500&36 — склейка кода модели и номера в мониторинге
  • Защита при разборе: внешние сущности и сетевые обращения отключены, ограничения библиотеки не снимаются — подготовленный файл-бомба отвергается за доли секунды
Ключевой нюанс

Два набора данных и два режима просмотра

В файле две методики учёта одновременно

  • По графику смен — учитывается только рабочее время смен
  • По календарным суткам — все 24 часа, включая ночь и выходные

Это одни и те же события, посчитанные по-разному. Сложить их вместе — значит удвоить время. В интерфейсе сделан явный переключатель «Учёт времени», а не молчаливый выбор одного из наборов.

Просмотр по файлу или по датам

  • По файлу — показывается ровно содержимое выбранной выгрузки
  • По датам — произвольный диапазон поверх всех загруженных файлов

Выгрузки перекрываются по периодам. На каждые сутки берутся данные самой свежей выгрузки, которая эти сутки содержит — задвоения исключены. В интерфейсе видно, какие сутки из какого файла взяты.

Перекрытие выгрузок и выбор источника
Выгрузка от 05.09  · 01.09 — 08.09
Выгрузка от 12.09  · 05.09 — 15.09
Выгрузка от 17.09  · 09.09 — 17.09
За сутки 05.09—08.09 берётся выгрузка от 12.09, за 09.09 и далее — от 17.09. Каждые сутки попадают в отчёт ровно один раз.
Методика

Как считаются показатели

Каждый процент в интерфейсе подписан: что делится на что. Числитель и знаменатель видны рядом с цифрой, чтобы показатель можно было проверить.

Коэффициент загрузки
время в состоянии «Работа по программе» (код 0101)всё учтённое время за период
Загрузка при включённом станке
время в состоянии «Работа по программе»учтённое время − «Выключено» − «Нет данных» (0001, 0002)
Простои
Всё остальное время: наладка, отсутствие задания, авария, ремонт, организационные простои. Разложено по группам состояний из самой выгрузки.

Структура суток станка

Работа 41%
Простой 24%
Выключено 35%

Коэффициент загрузки в этом примере — 41%: работа делится на все 24 часа. Загрузка при включённом станке — 63%: те же часы работы делятся только на время, когда станок был включён.

Два показателя отвечают на разные вопросы: первый — насколько занято оборудование в целом, второй — насколько эффективно используется смена, когда станок работает.

Справочник

Как идентификатор превращается в станок

В выгрузке о станке известен только идентификатор интеграции. Паспортные данные подгружаются из Excel и подставляются во все отчёты.

Из XML
MDM-C19-002147500 & 36
=
Код модели (MDM)
MDM-C19-002147500
+
Номер в мониторинге
36

Точная привязка

  • Основной формат — выгрузка станков из системы мониторинга
  • В ней есть колонка ID — тот самый номер после &
  • Вместе с кодом MDM даёт однозначное соответствие, угадывать не нужно

Запасной формат

  • Таблица присвоения кодов MDM: инвентарный номер и код, колонки ID нет
  • Код MDM общий для одинаковых моделей — у 15 станков одной модели он один
  • Карточки раскладываются по порядку и помечаются как предположительные, станок правится вручную

Что это даёт

  • Ключ карточки — инвентарный номер: 2868, 00002868 и 0002868 (12 (80)) — один станок
  • Повторный импорт обновляет карточки, а не плодит дубли
  • Съехавшие заголовки в выгрузке распознаются по содержимому колонок
  • Логины и пароли доступа к станкам из файла не читаются и в базу не попадают

Безопасность

Проверено до ввода в эксплуатацию

Проведён аудит с попытками реальных атак: подмена роли в токене, подбор пароля, XML-бомба, обход каталога, инъекции. Найденные слабые места закрыты и перепроверены.

Доступ

  • Пароли — bcrypt, минимум 8 символов
  • Роль берётся из базы, а не из токена: подменённый токен прав не даёт
  • Отключение пользователя обрывает его сессию немедленно
  • Система не может остаться без администратора
  • 10 неудачных попыток входа за 5 минут — и вход блокируется
  • Ответ на несуществующий логин занимает столько же времени, сколько на существующий

Приём данных

  • XML: внешние сущности и сетевые обращения отключены
  • Размер загрузки проверяется до разбора — переполнить память файлом нельзя
  • Имя файла очищается, на диск кладётся под своим именем: выход за каталог закрыт
  • Экспорт в CSV экранирует ячейки, чтобы данные из чужого файла не выполнились в Excel
  • Все запросы к базе параметризованы

Инфраструктура

  • Сервер приложения работает не от root
  • Защитные заголовки браузера, версии ПО скрыты
  • База данных наружу не публикуется
  • Служебная документация API на боевом сервере выключена
  • Обязательный HTTPS, перенаправление с 80 порта
  • Зависимости обновлены: проверки pip-audit и npm audit чисты

Честно о границах

Ограничения и развитие

Решения, принятые осознанно: они упрощают эксплуатацию сейчас, но их стоит знать заранее.

О чём стоит знать

  • Токен живёт 12 часов и не отзывается: выход из системы удаляет его только в браузере (отключение пользователя — аннулирует сразу)
  • Счётчик попыток входа живёт в памяти процесса: при нескольких копиях приложения понадобится общее хранилище
  • Любой вошедший пользователь может скачать исходный XML и выгрузить CSV — данные считаются доступными всем, у кого есть доступ
  • Журнал действий пользователей не ведётся, в логах только неудачные входы

Что можно добавить дальше

  • Автоматический приём выгрузок по расписанию — без ручной загрузки файла
  • Права на уровне цехов: пользователь видит только своё оборудование
  • Журнал действий и отзыв выданных токенов
  • Регулярные отчёты на почту: сводка за смену, неделю, месяц
  • Плановые показатели и отклонение факта от плана
  • Уведомления о простоях сверх нормы
