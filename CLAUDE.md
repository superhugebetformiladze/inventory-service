# CLAUDE.md — правила работы с этим репозиторием

## 0. Граница изменений

**Изменять файлы только внутри `D:\projects\inventory_service`.**

Соседний проект `D:\projects\AccountingSystemJSONB` — отдельная граница со
своими правилами (см. его `CLAUDE.md`). Потребитель ленты будет жить там, и
писать его надо там, а не здесь. Файл из одного проекта, положенный в каталог
другого, — ошибка, а не удобство.

## 1. Журнал обязателен

Каждое изменение файлов записывается в [`WORKLOG.md`](WORKLOG.md) **в том же
ответе**, что и само изменение. Не «поправил конфиг», а «вынес порт Postgres в
переменную, потому что 5433 занят учётной системой».

## 2. С чего начинать

[`docs/PLAN.md`](docs/PLAN.md) — 12 этапов, инварианты, условия задачи и риски.
Читать первым. Следующий этап не начинается, пока не выполнен Definition of
Done текущего.

## 3. Инварианты

Полный список с обоснованиями — в `docs/PLAN.md` §2. Кратко, нарушение любого
из них — дефект, даже если код работает:

| # | Инвариант |
|---|---|
| I1 | Сервис не знает своих потребителей: ни `Entity`, ни «инвентарный номер» в коде и контракте |
| I2 | Запись в БД и публикация события — одна транзакция через outbox |
| I3 | Каждый обработчик идемпотентен |
| I4 | Ключ сообщения в ленте — идентификатор хоста |
| I5 | Контракт меняется только добавлением полей |
| I6 | Агент не выполняет произвольных команд |
| I7 | Отчёт принимается только с действующим ключом машины |
| I8 | Неопознанная машина не заводит запись сама |
| I9 | Событие публикуется только при фактическом расхождении |
| I10 | Секретов в коде нет; нет переменной — служба не стартует |
| I11 | Каждый внешний вызов с `context` и таймаутом |
| I12 | Миграции только вперёд, в entrypoint не запускаются |

## 4. Технические соглашения

* Go, PostgreSQL 16, Kafka (на разработке Redpanda). Версия Go — в `go.mod`.
* **Всё запускается в контейнере:** `make ci`, `make test`, `make lint`.
  Локальный `go test` прогоном не считается — важно, чтобы у всех и в CI
  результат был один.
* На Windows `make` не установлен: те же цели через `.\make.ps1 <цель>`.
* Комментарии и docstring — на русском, код и идентификаторы — на английском.
  Имена тестов допускают русский: они читаются как описание поведения.
* Комментарий объясняет **почему**, а не что: «что» видно из кода.
* Зависимость не добавляется без обоснования в `WORKLOG.md`. Стандартной
  библиотеки хватает чаще, чем кажется.
* Концы строк — LF (см. `.gitattributes`), иначе `gofmt` в контейнере краснеет
  на правке, которой не было.
* `make.ps1` сохраняется **в UTF-8 с BOM**. PowerShell 5.1 без BOM читает файл
  как ANSI: кириллица разваливается, ломает кавычки, и скрипт перестаёт
  разбираться целиком.

## 5. Чего не делать

* Не коммитить и не пушить без явной просьбы.
* Не класть секреты в файлы репозитория — только `.env`, который в `.gitignore`.
* Не давать секретам значений по умолчанию в коде (I10).
* Не расширять список команд агента «на будущее»: канал произвольных команд к
  парку машин — это средство удалённого управления всей сетью (I6).
