# XML Parser — мониторинг оборудования

Разбор XML-выгрузок системы мониторинга станков (`XmlDataWrapper`), хранение их в PostgreSQL
и веб-интерфейс: админка для загрузки файлов и клиентская аналитика по станкам, состояниям,
сменам и суткам.

## Запуск

```bash
cp .env.example .env        # поправьте пароли
docker compose up -d --build
```

Это конфигурация для разработки и ознакомления. Для боевого сервера —
[DEPLOY.md](DEPLOY.md): HTTPS, закрытый порт API, автозапуск, бэкапы.

- Интерфейс: http://localhost:8080
- API и Swagger: http://localhost:8000/api/health, http://localhost:8000/docs
- Первый вход: `admin` / `admin` (значения из `.env`, меняются в разделе «Пользователи»).

Загрузите XML в «Админка → Файлы» — данные сразу появятся в разделе «Аналитика».
Пример файла лежит в `sample_data/`.

## Что внутри файла

| Секция XML | Смысл |
|---|---|
| `DateLastReplication` | метаданные выгрузки: когда сформирована, за какой период |
| `Machine` | станки: `ID` + `IntegrationID` |
| `MachineParam` | состояния: работа по программе, простой, авария, наладка… + цвет |
| `GroupParam` / `MachineParamInGroup` | группы состояний (Тмаш, Тпрос.орг, Тобсл …) |
| `rep_MonitoringByPriority` | основные данные: станок × состояние × сутки × смена + длительность (`PT6H52M37S`) |
| `SheduleMeta` / `SheduleBase` / `SheduleBaseItem` | графики смен |

Ключевой нюанс: в `rep_MonitoringByPriority` два параллельных набора данных.

- `SheduleTypeID = 1` — учёт **по графику смен** (только рабочее время смен);
- `SheduleTypeID = 2` — учёт **по календарным суткам** (все 24 часа).

Суммировать их вместе нельзя — в интерфейсе это переключатель «Учёт времени».

## Три режима просмотра

1. **По файлу** — выбирается конкретная выгрузка, показывается ровно её содержимое.
2. **По датам** — диапазон дат поверх всех загруженных файлов. Периоды выгрузок обычно
   перекрываются, поэтому на каждые сутки берутся данные **самой свежей** выгрузки,
   содержащей эти сутки (см. `resolve_day_sources` в `backend/app/services/analytics.py`).
   Задвоения исключены.
3. **За всё время** — то же, что «по датам», но без границ периода: в выборку попадают
   все загруженные сутки. Дедупликация та же, поэтому перекрытия выгрузок не задваиваются.
   В адресе это `scope=all`; присланные вместе с ним даты сознательно отбрасываются,
   чтобы забытый в ссылке фильтр не сузил выборку незаметно.

Режим действует на дашборде, на странице станка и в выгрузке CSV. В разделе «Продукция»
у списка плана и факта есть такой же переключатель «За период / За всё время».

## Карточки оборудования

В XML о станке известен только `IntegrationID` вида `MDM-C19-002147500&36`. Паспортные
данные подгружаются из Excel в «Админка → Оборудование». Ключ карточки — инвентарный
номер, поэтому повторный импорт обновляет карточки, а не плодит дубли; номера вида
`2868`, `00002868` и `0002868 (12 (80))` считаются одним и тем же станком.

**Основной формат — выгрузка станков из системы мониторинга** (`..._machines.xlsx`).
На листе есть колонка `ID` — это идентификатор станка в мониторинге, тот самый суффикс
после `&`. Вместе с `Код_MDM` он даёт точную привязку: `MDM-C19-002147500` + `36`
→ `MDM-C19-002147500&36`. Ничего угадывать не нужно.

Подхватываются: `ID`, `Инвентарный_номер`, `Модель`, `Описание`, `IP_адрес`, `Имя_УЧПУ`,
`Тип_УЧПУ`, `Цех`, `Код_MDM`, а также английские заголовки технического листа
(`INV_NUM`, `MODEL`, `DESCRIPTION`, `IP`, `MDM`). Все листы книги читаются и дополняют
друг друга. **Логины и пароли доступа к станкам, если они есть в файле, не читаются
и в базу не попадают.**

Если на техническом листе заголовки съехали относительно данных (так бывает в выгрузке:
код MDM лежит под заголовком `UPLOAD_VKO`), импорт определяет это по содержимому колонок
и берёт с такого листа только то, что можно проверить по формату — код MDM, IP и ID,
плюс колонки до первой сбившейся. Остальное берётся с листов с нормальными заголовками.

**Запасной формат — таблица для присвоения кодов MDM** (`Инв.№` + `ID MDM`, без колонки
`ID`). Точной привязки в ней нет: код MDM общий для одинаковых моделей (у 15 станков
MCV 800 QUICK он один), поэтому карточки раскладываются по порядку и помечаются как
предположительные — в админке они подсвечены, станок меняется выпадающим списком.
Такую таблицу удобно загружать вторым файлом: она дополнит карточки цехом и системой ЧПУ,
не тронув точные привязки.

Отчёт импорта показывает, что привязано точно, что по порядку, какие карточки остались
без станка и какие станки без карточки.

Название из карточки подставляется во все отчёты вместо `IntegrationID`, а по клику
на станок открывается его страница: паспорт, показатели за период, место в парке,
структура времени, динамика по суткам и разбивка по состояниям.

## Продукция: план и факт

Что станок делает и сколько сделал — отдельный слой данных поверх мониторинга.

**Источник — рапорт** «Справка о выполнении плана производства заготовительными цехами»
(Excel). Файл устроен блоками по цехам: строка цеха с итогами, под ней номенклатура
с колонками «План», «Сдано на склад ПДО», «Возврат со склада ПДО», «Примечание»,
в конце — «Итого». Разбор находит шапку по колонке «План» (она двухуровневая: «План»
и «Сдано» стоят строкой выше, чем «Номенклатура» и «Тип корпуса») и складывает только
строки номенклатуры — итоговые строки цехов и «Итого» в базу не попадают, они идут
на сверку: если сумма разобранных строк не сошлась с итогом файла, об этом пишется
в отчёте загрузки.

Две особенности рапорта определяют всё остальное:

- **станков в нём нет** — он составляется по цехам. Поэтому связь «станок → изделие»
  заводится вручную в «Админка → Продукция → Номенклатура и станки»;
- **периода в нём тоже нет** — за какой месяц справка, знает только тот, кто её выгрузил.
  Период указывается при загрузке, по умолчанию подставляется текущий месяц. Рапорт
  за уже занятый период не примется без подтверждения, иначе план и факт задвоятся.

**Ключ номенклатуры** — название + тип корпуса + цех. Повторная загрузка находит уже
заведённое изделие и не плодит дубли.

**Ручной ввод** («Добавить вручную») нужен, когда рапорта нет или когда выпуск надо
записать именно на станок: у ручной строки, в отличие от строки из рапорта, можно
указать станок. Изделие при этом либо выбирается из справочника, либо заводится тут же.

**На странице станка** появляется блок «Продукция»: закреплённые изделия, план, факт
и процент выполнения за тот же период, что и показатели загрузки. Если изделие делают
несколько станков, строка помечена «на N станках» — цифры там общие на все эти станки,
а не выпуск одного. Точные цифры по станку дают ручные строки с указанием станка.

**На дашборде** — блок «План и факт производства»: итог по всей номенклатуре и разрез
по цехам. Пока в справочнике нет ни одного изделия, блок не показывается. В режиме
«за всё время» план и факт тоже берутся без ограничения по датам.

**Отдельная страница «Продукция»** (пункт меню рядом с «Аналитикой») собирает всё вместе:

- фильтры — период или «за всё время», цех, поиск по названию изделия; они живут
  в адресе страницы, поэтому ссылкой на нужный разрез можно поделиться;
- показатели: план, сдано, выполнение плана, возврат, число позиций номенклатуры;
- две круговые диаграммы — распределение выпуска по цехам и по изделиям. Показываются
  пять крупнейших долей, остальное складывается в «Прочие»: при большем числе секторов
  соседние цвета перестают различаться. Рядом с каждой диаграммой лежит список
  с числами, поэтому цвет никогда не единственный способ понять, где что;
- таблица с правкой **прямо в строке**: по кнопке «править» план, факт, возврат, станок
  и примечание превращаются в поля ввода. Пустое поле сохраняется как «значения нет»,
  а не как ноль;
- кнопка «Добавить строку» — ручной ввод новой позиции;
- кнопка «Выгрузить в Excel».

Период по умолчанию — тот, за который загружен последний рапорт, а не текущий месяц:
иначе в начале месяца страница открывалась бы пустой при наличии данных.

Все числа страницы (показатели, обе диаграммы, итоги таблицы) считаются из одних и тех же
строк, которые видны в таблице, — разойтись они не могут.

### Выгрузка в Excel

`Продукция → Выгрузить в Excel` отдаёт книгу ровно по текущей выборке — с теми же
фильтрами периода, цеха и поиска. В книге четыре листа:

| Лист | Что внутри |
|---|---|
| План и факт | строки выборки: изделие, цех, станок, период, план, факт, выполнение, возврат, источник, примечание |
| Свод по цехам | план, факт, выполнение и число строк по каждому цеху |
| Свод по изделиям | то же в разрезе номенклатуры |
| О выгрузке | за какой период, когда сформирована и итоговые цифры |

Числа кладутся числами, а не текстом, даты — датами, поэтому в Excel сразу работают
суммы и сводные таблицы. Шапка закреплена, включён автофильтр (строку «Итого» он
не захватывает, чтобы сортировка не утащила её в середину). Значения, начинающиеся
с `=`, `+`, `-`, `@`, помечаются апострофом — Excel покажет их текстом, а не выполнит
как формулу.

Выполнение плана считается как **сдано ÷ план**. Там, где плана нет (в рапорте пустая
клетка), процента нет тоже — ноль и «плана не было» это разные вещи.

## Показатели

- **Коэффициент загрузки** = «Работа по программе» (код `0101`) / всё учтённое время.
- **Загрузка при включённом станке** — то же, но без времени «Оборудование выключено»
  и «Нет данных» (коды `0001`, `0002`).
- **Простои** = всё остальное: наладка, отсутствие задания, авария, ремонт и т. д.

## Безопасность

Что сделано в коде:

**Аутентификация и доступ**
- пароли — bcrypt (длиннее 72 байт обрезаются, а не роняют API), минимум 8 символов;
- JWT подписывается `SECRET_KEY`; если он не задан, генерируется случайный + предупреждение
  в лог — ключ из примера конфига не используется никогда; токены с `alg=none`, чужой
  подписью или просроченные отвергаются;
- роль берётся из БД, а не из токена: подменённый `role` в payload прав не даёт;
- отключение или удаление пользователя обрывает его сессию немедленно;
- система не может остаться без администратора — снять роль, отключить или удалить
  последнего действующего админа нельзя;
- вход ограничен: 10 неудачных попыток на «логин + IP» за 5 минут, дальше `429`
  (реальный IP из `X-Forwarded-For`, но только от прокси из приватной сети);
- ответ на несуществующий логин занимает столько же времени, сколько на существующий.

**Приём данных**
- XML: внешние сущности и сетевые обращения отключены (XXE закрыт), лимиты libxml2
  не снимаются — «billion laughs» отвергается за доли секунды без роста памяти;
- размер загрузки проверяется прямо при чтении потока, а middleware отсекает
  слишком большие тела запросов ещё до разбора (даже без авторизации);
- имя файла чистится от путей и управляющих символов, на диск кладётся под
  сгенерированным именем — обход каталога и инъекция в `Content-Disposition` невозможны;
- CSV-экспорт экранирует ячейки, начинающиеся с `=`, `+`, `-`, `@`, чтобы данные
  из чужого XML не выполнялись как формулы Excel;
- все запросы к БД параметризованы (SQLAlchemy), инъекции через фильтры не проходят.

**Инфраструктура**
- backend работает от непривилегированного пользователя, а не от root;
- nginx отдаёт `Content-Security-Policy`, `X-Frame-Options`, `X-Content-Type-Options`,
  `Referrer-Policy`; заголовки с версиями сервера скрыты;
- PostgreSQL наружу не публикуется;
- CORS по умолчанию выключен, открывается списком в `CORS_ORIGINS`;
- зависимости обновлены до версий без известных уязвимостей (`pip-audit` и `npm audit`
  чисты). Проверяйте периодически:
  ```bash
  docker run --rm -v "$PWD/backend:/src:ro" python:3.12-slim     sh -c "pip install -q pip-audit && pip-audit -r /src/requirements.txt"
  docker run --rm -v "$PWD/frontend:/src:ro" node:22-alpine     sh -c "mkdir -p /tmp/a && cd /tmp/a && cp /src/package.json . && npm i --package-lock-only -s && npm audit"
  ```

### Чек-лист перед деплоем

1. `SECRET_KEY` — свой, случайный: `python -c "import secrets; print(secrets.token_urlsafe(48))"`.
2. `POSTGRES_PASSWORD` и `ADMIN_PASSWORD` — свои; после первого входа сменить пароль
   администратора в разделе «Пользователи».
3. HTTPS обязателен: иначе токен и пароли идут открытым текстом. При терминации TLS
   на этом же nginx добавьте `Strict-Transport-Security`.
4. Убрать публикацию порта API наружу — в `docker-compose.yml` удалить блок `ports`
   у сервиса `backend`, доступ останется через nginx.
5. `ENABLE_DOCS=false` — Swagger на проде не нужен.
6. Настроить бэкап тома `pgdata` (данные) и `uploads` (исходные XML).

### Ограничения, о которых стоит знать

- токен живёт 12 часов и не отзывается: «Выйти» удаляет его только в браузере, смена
  пароля ранее выданные токены не аннулирует (отключение пользователя — аннулирует);
- токен хранится в `localStorage` — при появлении XSS он будет доступен скрипту;
  CSP это затрудняет, но не отменяет;
- счётчик попыток входа живёт в памяти процесса: при нескольких воркерах или репликах
  у каждого свой лимит (нужен Redis);
- любой авторизованный пользователь может скачать исходный XML и выгрузить CSV —
  данные считаются доступными всем, у кого есть вход;
- приложение ходит в БД под владельцем схемы (нужно для `create_all` при старте);
- аудит действий не ведётся: в логах есть только неудачные входы.
